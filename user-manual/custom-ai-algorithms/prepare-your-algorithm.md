# Prepare your Algorithm

This section will show how to perform the setup of a simple custom algorithm.

## File Structure

The file structure must be the following:

```sh
<algo_name>
     ├── Dockerfile_dev [Optional]
     ├── (...)
     └── <algo_name>
              ├── main.py
              ├── *_model.py
              ├── (...)
              └── model_manifest.yml
```

All the models must also have a config.yml configuration file, but this file is automatically generated by running the following code in the root folder of the custom algorithm:

```sh
(py397) python -c "from mywai_python_backend.utils.config_handler import generate_models_config_and_clear; generate_models_config_and_clear()"
```

> The files indicated as **optional** refer only to the dockerised version of the algorithm.

The code can be structured as desired, with an indefinite number of modules and files, the only constraint being the project structure shown here.

### Creating the model file

Every custom algorithm must have a "**\*\_model.py**" file. This file contains the implemented custom model class. The class name is the '**Unique Algorithm ID'** and its static variables will be used for the automatic generation of configuration files.&#x20;

The class that handles this model must be an inheritance of the **MywAIModel** class or a further subclass of it (e.g. **AnomalyDetectionModel**).

The following code shows an example of a custom algorithm, having DummyModel as **Unique Algorithm ID:**

```python
from __future__ import annotations

from mywai_python_backend.data.data import MyWAIDataType
from mywai_python_backend.models.anomaly_detection.anomaly_detection_model import (
    AnomalyDetectionModel,
)

class DummyModel(AnomalyDetectionModel):
    """
    Dummy Custom Model for debugging purposes
    """
    data_type = [MyWAIDataType.images]
    user_friendly_name = "Dummy Custom Model"
    category = MyWaiModelCategory.anomaly_detection
    
    def __init__(self):
        super().__init__()

    def compute_anomalies(self, *args, **kwargs):
        super().compute_anomalies(*args, **kwargs)

    def train(self, *args, **kwargs):
        pass

    def predict(self, *args, **kwargs):
        pass

    def save(self, *args, **kwargs):
        pass

    @staticmethod
    def load(*args, **kwargs):
        pass

    def export(self):
        return super().export()

    @staticmethod
    def import_(encoded_object):
        return super().import_(encoded_object)

    def copy(self):
        return super().copy()

    def set_inference_parameters(self, *args, **kwargs):
        pass

    @staticmethod
    def create_html(*args, **kwargs):
        return super().create_html(*args, **kwargs)
    
```

Some key information:

1. The **data\_type** is a list of the data supported by this specific algorithm. The supported data types are available as attributes within the **MyWAIDataType** class.
2. The **user\_friendly\_name** is the name that will be displayed for this algorithm within MYWAI's software infrastructure.
3. The **category** is the model functional target, like "anomaly\_detection" or "classification". The supported categories are available as attributes within the **MyWaiModelCategory** class.

### Model Manifest

Every model must have a model\_manifest.yml file configured as:

```yaml
model:
  description: "A dummy custom model"

training_parameters:
  - name: "useless_training_param"
    type: "int"
    user_friendly_name: "Useless Training Param"
    description: "foo"
    min: 1
    max: 1024
    default: 16
    options: []

inference_parameters:
  - name: "useless_inference_param"
    type: "int"
    user_friendly_name: "Useless Inference Param"
    description: "foo"
    min: 1
    max: 1024
    default: 16
    options: []
```

Where **training\_parameters** and **inference\_parameters** are parameter lists and can be empty. These are Training/Inference parameters of the model and will be used for the automatic configuration of the MYWAI interface.

### Model Entry Point

Every model must have a **main.py** entry point, like the following:

```python
from __future__ import annotations

import json
from typing import Optional

from mywai_python_backend.data.image_roi import MyWaiRoi
from mywai_python_backend.data.images_data import ImagesData
from mywai_python_backend.utils.utils import create_current_time_stamp


def train(data: ImagesData, algo_params: dict):
    return dict(model=None), []


def inference(
    training_results: dict,
    data: ImagesData,
    algo_params: Optional[dict] = None,
) -> MyWaiRoi:
    return MyWaiRoi(
        x=50,
        y=50,
        width=50,
        height=50,
    )


def create_inference_json_output(
    input_payload: dict, inference_output, inference_data: ImagesData
) -> str:
    json_results: dict = dict(blobs=[])
    # ...
    return json.dumps(json_results)

```

We must implement at least this three functions:

1. **train**: code to be execute during training mode
2. **inference**: code to be execute during inference mode
3. **create\_inference\_json\_output**: code to be executed downstream of the inference in order to manage the output of the inference within the MYWAI Platform (e.g. display of Rectangle Of Interest on images passed to the algorithm during inference).
