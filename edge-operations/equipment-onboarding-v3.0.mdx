# Equipment onboarding (v3.0)

The security of the connection between the Edge and the OPC-UA equipment can be configured in different ways, depending on:

* the security capabilities of the equipment, and
* the customer’s security requirements.

The recommended solution is to use the MYWAI GDS (Global Discovery Server) to provide PKI-based security using X.509 certificates and trust lists.

## Equipment **with** OPC-UA GDS support

If the OPC UA server embedded in the equipment natively supports the OPC-UA GDS protocol:

* Configure the MYWAI GDS endpoint in the OPC-UA server (refer to the equipment’s documentation for how to set this).
* Once configured, onboarding is handled automatically.
* The GDS will:
  * issue and deliver the X.509 certificate to the OPC UA server,
  * provide the trust list containing the client certificates allowed to connect.

No additional manual import/export of certificates is required.

## Equipment **without** OPC-UA GDS support

If the OPC UA server does not support GDS, but accepts TLS-secured authenticated connections:

* Use the MYWAI command line tool to register the equipment in the GDS and obtain its certificate.
* The tool will generate:
  * the private key,
  * the signed public certificate,
  * the trust list.
* These artifacts must then be manually installed on the OPC UA server.
  Consult the equipment documentation for the import procedure.

### Onboarding using the MYWAI command line tool

#### Step 0 — Download the tool

[Download GDSCommand.zip](/assets/GDSCommand.zip)

#### Step 1 — Configure `appsettings.json`<br>

Specify the GDS connection parameters:

```json
"GDS": {
    "port": 58810,
    "address": "localhost",
    "useTPM": false,
    "user": "appadmin",
    "password": "demo"
}
```

If the GDS is running on the same device as the command line tool, use:

* `localhost` as `address`
* `58810` as `port`

For the `password` field, set the same password choosed during the GDS installation.
If not set, the default password is "demo".

Set `useTPM` to `true` if you intended to store the private key only inside the TPM (Trusted Platform Module) chip, if available, inside the current device. You can use this option only when running the command line only directly on the OPCUA Server device of your equipment.

#### Step 2 — Create the application description file

Create a JSON file describing the OPC-UA server application to be onboarded.
This file is used by the tool to register the equipment application into the GDS and request its certificate.

```json
{
    "ApplicationRecordDataType": {
        "ApplicationUri": "opc.tcp://myequipment:9200/OPCUA/Server",
        "ApplicationType": 0, // Server
        "ApplicationNames": [
            {
                "Locale": "EN-US",
                "Text": "My equipment"
            }
        ],
        "ProductUri": "opc.tcp://myequipment:9200/OPCUA/Server",
        "DiscoveryUrls": [ "opc.tcp://myequipment:9200/OPCUA/Server" ],
        "ServerCapabilities": [ "DA" ]
    }
}
```

Here the description of the field values (ref [https://reference.opcfoundation.org/GDS/v105/docs/6.5.5](https://reference.opcfoundation.org/GDS/v105/docs/6.5.5)):

<table><thead><tr><th width="202">Field name</th><th>Value</th></tr></thead><tbody><tr><td>ApplicationUri</td><td>The URI for the Application</td></tr><tr><td>ApplicationType</td><td>The application type. Use "0" for OPC-UA servers.</td></tr><tr><td>ApplicationNames</td><td><p>One or more localized names for the application.</p><p>The first element is the default ApplicationName for the application when a non-localized name is needed.</p></td></tr><tr><td>ProductUri</td><td><p>A globally unique URI for the product associated with the application.</p><p>This URI is assigned by the vendor of the application.</p></td></tr><tr><td>DiscoveryUrls</td><td><p>The list of discovery URLs for the application.</p><p>The first HTTPS URL specifies the domain used as the Common Name of HTTPS Certificates.</p></td></tr><tr><td>ServerCapabilities</td><td>Use this <a href="https://reference.opcfoundation.org/GDS/v105/docs/D#_Ref354721284">reference </a>and the equipment vendor documentation to provide a list of capabilities.<br>This value is currently not used by MYWAI, so it is not mandatory. Use "DA" in case you can't find proper information to fill up the list.</td></tr></tbody></table>

#### Step 3 —  Launch the tool

Run the following command to register the Equipment:

```batch
MywAi.Edge.GDSCommand.exe -file "MyApplication.json" -mode "register"
```

Where the `MyApplication.json` is the json file created at the previous step.
