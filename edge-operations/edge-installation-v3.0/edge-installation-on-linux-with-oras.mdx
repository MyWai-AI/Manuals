---
title: "Edge Installation on Linux"
---

Use this procedure to install MYWAI Edge on Ubuntu 22.04 (64-bit). ORAS is the tool that downloads the installation package for the version MYWAI gave you. You prepare the machine, sign in to the registry, fill in one configuration file, and start the package.

The same package also starts the **GDS** (Global Discovery Server) on this machine. The GDS is the OPC UA service that issues the certificates for the Edge and for the equipment. You do not install it separately: the start script runs the Edge container and the GDS container together. What the GDS does, and what you accept on the platform afterwards, is described in [Edge Installation](/edge-operations/edge-installation-v3.0/index#the-gds).

You need from MYWAI:

* the **version** to install, for example `3.1.30` 
* the **registry username** and **token**
* the **platform hostname**, the host in the platform address without `https://` (if the platform is `https://acme.platform.myw.ai`, the hostname is `acme.platform.myw.ai`)
* the **Edge ID** already created on the platform
* a **GDS ID** unique for this machine
* a **GDS password** that you choose and keep: the Edge uses it to talk to the GDS

The Edge ID must be exactly the identifier configured on the platform, and it must start with `Edge-` (for example `Edge-Acme-Line-1`). The same spelling is required in the configuration file below.

## 1. Install Docker Engine

Install Docker Engine with the official guide for Ubuntu: [https://docs.docker.com/engine/install/ubuntu/](https://docs.docker.com/engine/install/ubuntu/)

Install the Compose plugin and Python 3. The start script needs both.

```bash
sudo apt-get update
sudo apt-get install -y docker-compose-plugin python3 ca-certificates curl
```

Start Docker and enable it at boot:

```bash
sudo systemctl start docker
sudo systemctl enable docker
```

<Info>
You can apply the [post-install steps](https://docs.docker.com/engine/install/linux-postinstall) so your user can run Docker without `sudo`. If you do, omit `sudo` from the `docker` commands below. Creating `/opt/mywai` still needs `sudo` the first time.
</Info>

## 2. Install ORAS

Open [the ORAS releases page](https://github.com/oras-project/oras/releases) and copy the latest version number **without** the leading `v` (for example `1.2.3`).

On a typical PC (x86_64) run the following, with that version in `VERSION`:

```bash
VERSION=1.2.3
curl -LO "https://github.com/oras-project/oras/releases/download/v${VERSION}/oras_${VERSION}_linux_amd64.tar.gz"
sudo tar -zxf "oras_${VERSION}_linux_amd64.tar.gz" -C /usr/local/bin oras
rm "oras_${VERSION}_linux_amd64.tar.gz"
oras version
```

On an ARM64 machine, download `oras_${VERSION}_linux_arm64.tar.gz` instead of the `linux_amd64` archive.

`oras version` prints a version number.

## 3. Sign in to the registry

Use docker command to login to registry:

```bash
sudo docker login -u mywai-pull -p <token> mywaiprod.azurecr.io
```

A successful login prints `Login Succeeded`. ORAS uses this same login, so you do not sign in a second time.

<Warning>
Contact MYWAI to obtain the username and token. Keep the token private. If you enabled Docker for your user, run `docker login` without `sudo`, otherwise ORAS (which runs as your user) will not see the credentials.
</Warning>

## 4. Create the folders

The installation lives under `/opt/mywai`. Data folders stay **outside** `/opt/mywai/releases`, so an update can replace the software without deleting certificates and collected files.

Create the root so your user owns it, then create one data folder per identity. Replace the example IDs with yours:

```bash
sudo mkdir -p /opt/mywai
sudo chown "$USER":"$USER" /opt/mywai

mkdir -p \
  /opt/mywai/releases \
  /opt/mywai/data/Edge-Acme-Line-1/edge-io \
  /opt/mywai/data/Edge-Acme-Line-1/edge-storage \
  /opt/mywai/data/Gds-Acme-1/gds-storage
```

Use a GDS data folder that belongs only to this GDS ID. A folder already used by another GDS keeps that GDS certificate and the new GDS will refuse to start.

## 5. Download the package

Replace `<version> (with value 3.1.60)`

```bash
oras pull mywaiprod.azurecr.io/edge-deploy:<version> --output /opt/mywai/releases/<version>
```

This creates `/opt/mywai/releases/<version>/edge/`. That folder contains the configuration template and the start script. You use it in the next steps. The script will download the same package again when it starts the services, and that second download checks that the package matches the version you asked for.

## 6. Create `edge.env`

Copy the template to `/opt/mywai/edge.env`. This file is the configuration of **this machine**. Later updates leave it in place and only write the registry and the version into it.

```bash
cp /opt/mywai/releases/<version>/edge/.env.example /opt/mywai/edge.env
nano /opt/mywai/edge.env
```

Set these values. Leave `REGISTRY` and `PLATFORM_VERSION` empty: the start script fills them.

```
EDGE_ID=Edge-Acme-Line-1
GDS_ID=Gds-Acme-1
GDS_PASSWORD=<password-you-choose>

IOTHUB_SERVER=iothub.acme.platform.myw.ai
IOTHUB_MQTT_PORT=8883
BLOB_SFTP_SERVER=sftp.acme.platform.myw.ai
BLOB_SFTP_PORT=22
BLOB_PUBLIC_URL=https://acme.platform.myw.ai/blobs

EDGE_IO_DIR=/opt/mywai/data/Edge-Acme-Line-1/edge-io
EDGE_STORAGE_DIR=/opt/mywai/data/Edge-Acme-Line-1/edge-storage
GDS_STORAGE_DIR=/opt/mywai/data/Gds-Acme-1/gds-storage
```

| Field | What you enter |
| --- | --- |
| `EDGE_ID` | The Edge ID from the platform. It must start with `Edge-`. |
| `GDS_ID` | A name unique for this GDS inside the tenant. |
| `GDS_PASSWORD` | The password the Edge uses to connect to the GDS. Remember it for equipment onboarding. |
| `IOTHUB_SERVER` | `iothub.` followed by the platform hostname. |
| `IOTHUB_MQTT_PORT` | `8883`, unless MYWAI gave you another MQTT port. |
| `BLOB_SFTP_SERVER` | `sftp.` followed by the platform hostname. |
| `BLOB_SFTP_PORT` | `22`, unless MYWAI gave you another SFTP port. |
| `BLOB_PUBLIC_URL` | `https://` + platform hostname + `/blobs`. |
| `EDGE_IO_DIR` | The `edge-io` folder you created for this Edge ID. |
| `EDGE_STORAGE_DIR` | The `edge-storage` folder you created for this Edge ID. |
| `GDS_STORAGE_DIR` | The `gds-storage` folder you created for this GDS ID. |

The machine must be able to reach `iothub.<platform hostname>` and `sftp.<platform hostname>` on the network.

## 7. Start Edge and GDS

Run the script from the package you just downloaded. Replace `<version>`:

```bash
bash /opt/mywai/releases/<version>/edge/scripts/update.sh <version> --root /opt/mywai --up
```

You pass:

* the version — the same version you downloaded (3.1.60)
* `--root /opt/mywai` — the folder that contains `edge.env`
* `--up` — start the containers after the check

The script then:

1. downloads the package again (or reuses it if it is already complete on disk)
2. writes `REGISTRY` and `PLATFORM_VERSION` into `/opt/mywai/edge.env`
3. makes `/opt/mywai/edge` point at this version
4. checks the compose file
5. starts the Edge and the GDS

At the end it prints the container list. `edge` and `gds` are running when their state is `running`.

Open the Edge dashboard at `http://localhost:8090`.

The GDS OPC UA endpoint on this machine is `opc.tcp://localhost:58810/GlobalDiscoveryServer`. The local MQTT broker for field devices listens on port `1883`.

## 8. Accept the GDS on the platform

On the platform, open the [GDS list](/configuration/gds-v3.0). The new GDS appears as a join request. Accept it.

After you accept it, the platform sends the GDS certificate. The Edge then asks that GDS for its own certificate. If the Edge stays offline, check that `EDGE_ID` in `edge.env` is identical to the Edge ID on the platform, including the `Edge-` prefix.

## Update to a newer version

Ask MYWAI for the new version, then run the script from the installation that is already active. You do not edit `edge.env` and you do not download the package by hand:

```bash
bash /opt/mywai/edge/scripts/update.sh <new-version> --up
```

The previous package stays in `/opt/mywai/releases`. To go back, run the same command with the previous version.
