---
title: "Use case: interact with sensor and gather data"
---

Here an example of the usage of the Platform APIs to:

* Start a stop the data recording for a Sensor
* Gather timeseries sensor data

## Obtain sensor ID

If you don't know the sensor ID, follow these steps:

1. Perform a GET to the `/api/equipment/getallLight` endpoint to retrieve a list of all equipment. In the response, identify the equipment to which your sensor is attached (for example, by the equipment name) and note the Equipment ID. Alternatively, you can ask the end user to select the relevant equipment.
2. Next, perform a GET to `/api/sensor/getAllSensorByEquipmentRoot/<equipmentId>`  with the obtained Equipment ID to get a list of all sensors associated with that equipment and find the ID of the sensor you need.

## Gather sensor measures identifier and configuration

Use the `/api/sensor/getSensorInfo/<sensorId>` endpoint (POST) to retrieve the identifiers of the measures associated with the sensor.

Save the sensor configuration found in the `"sensorMeasures"` field, as this will be needed to request the recorded sensor data.

## Start and stop the sensor

To start data acquisition, do a POST on `/api/detections/remote/true`. The payload should include the list of sensor measures you want the platform to collect data from at the Edge.

```json
{
    "iotDevice": "MyEdge", # Gather the actual Edge device name from the Equipment info
    "selectedSensorMeasures": [ 1, 2, 3, 4, 5 ] # Gather the actual sensor measures IDs from the getSensorInfo response
}
```

To stop the sensor, use the same call but to the URL: `/api/detections/remote/false`

## Gather the recorded data

To retrieve all recorded data, do a POST to the endpoint `/api/detections/get/<raw>`, where `<raw>` can be set to `"true"` for raw data or `"false"` for a downsampled version suitable for graph visualization.

Data can be retrieved for any specified time interval, independent of the start/stop calls made previously. The system will provide the recorded data available within the given time range, if it exists.

<Warning>
Avoid using the `<raw>=true` call for large time ranges, as it may result in an excessive amount of data being returned. Choose appropriate time ranges based on the data frequency to prevent the overall response from becoming too large.
</Warning>
