## **Understanding Sensors**

Whether physical or virtual, sensors allows a flexible way to gather data from a machine.

The platform comes with a built-it set of Adapters that allows the Edge device to gather data from the field using the most common protocols:

* OPC UA
* HTTP
* RTSP
* File system
* Bluetooth

<Warning>
In presence of an OPC server, the **use of Sensors is completely optional**, since the platform is able to connect the Equipment to the OPC UA server directly without the need to configure any additional Sensor. See [Equipment Types](/configuration/equipment-types) section.
</Warning>

### **Attributes of a Sensor**

1. **Name (Mandatory):** Every sensor has a unique identifier, ensuring clarity in distinguishing between multiple devices. It is recommended to follow the [ANSI/ISA-5.1-2009](http://integrated.cc/cse/Instrumentation_Symbols_and_Identification.pdf) standard.
2. **Type (Mandatory):** Sensors are classified into:
   * Generic
   * Camera
   * Microphone
3.  **Associated Measures:** A sensor could be linked to one or multiple [Measures](/configuration/measures), each dictating the type of data the sensor would capture.

    For each measure linked to the sensor:

    * **Frequency:** How often the sensor records or sends the data.
    * **Unit:** The standardized metric in which data is captured (e.g., Celsius, Hertz).
    * **Min and Max Value:** The range within which the recorded data is expected to fall.
4.  **Adapter (Mandatory):** This is the mode through which the sensor interfaces with the system. Available adapters include:

    * OPC UA
    * Bluetooth[^1]
    * [File System Watcher](/configuration/sensors/file-system-watcher-adapter)
    * [HTTP API polling](/configuration/sensors/http-api-polling-adapter)

    You could find additional items in the adapter list, according to your business needs.
5. **Serial Number (Mandatory):** A unique code allocated to every sensor, assisting in its identification and tracking.
6. **Firmware Version (Mandatory):** The version of the software embedded in the sensor, crucial for maintenance and updates.
7. **Description:** A brief overview or specifics regarding the sensor’s utility or features.
8. **Associated Site and Area:** Pinpointing the exact or relative location of the sensor within an environment.
9. **Image:** A visual representation, aiding in the sensor's identification or showcasing its design.

## **Sensors Management Page**

The page shows the list of the already configured Sensors.

* **Editing and Cloning:** Each entry in the list offers options to edit its attributes or clone it, providing a shortcut to replicate similar sensors.

<Info>
Once a sensor is created, the associated Measures cannot be changed or removed. Only new Measures can be added to the sensor.
</Info>

* **Deletion:** Sensors that are obsolete or redundant can be removed from the system with ease.
* **Manual Data Import:** An exclusive feature that allows users to manually feed data corresponding to a sensor's measures, ensuring flexibility. See [Data Import (old)](/configuration/sensors/data-import-old) for more details.
* **Adding New Sensors:** The "Add new sensor" button stands out, facilitating users to expand the system's sensing capabilities.
* **Associating with Equipments:** While in the [Equipment ](/configuration/equipments)edit panel, sensors can be tethered to specific equipment, enabling cohesive data capture. Associated equipment is shown in the related Equipment column in the sensor list.

<Warning>
Sensors and Equipment must belong to the same Site and Area to be linked together.
</Warning>

[^1]: Due to the flexibility of the Bluetooth protocol to carry many different type of data, only some special cases of data structure are managed by this adapter.
