**Train** opens a guided window. You move through it with **Next** and **Back**. The footer shows the current step, for example **Step 3 of 7**. **Cancel** closes the window without starting a run. On the last step, **Next** is replaced by **Train**.

A step you have already opened stays clickable in the bar at the top, so you can jump back to it. **Next** stays disabled until the current step has the choices it requires.

The window title depends on where you opened it:

* **Train model on selected labels** — from a label or tag on the [Data Analysis](/3.2/analysis/data-analysis) chart (**Train** in the row menu).
* **Train model on selected tags** or **Train model on selected categories** — from image tags or categories.
* **Train model on** a dataset name and version — from **Train Version** on a [DataSet](/3.2/analysis/datasets) version.

When the data is already a dataset version, the window starts at **Service**. When you still have to choose labels, tags, or categories, it starts with an extra **Data** step.

## Data

This step is shown only when the training is not already bound to a dataset version.

Select at least one card. A selected card is highlighted. **Next** stays disabled until one card is selected.

| Source     | What you pick                                                         |
| ---------- | --------------------------------------------------------------------- |
| Labels     | Label groups. Each card shows how many samples it contains.           |
| Tags       | Tags. Each card shows how many regions of interest it contains. A tag with none cannot be selected. |
| Categories | Categories. Each card shows how many items it contains. A category with none cannot be selected. |

If nothing is available, the step says so (for example **No labels available to train on**).

## Service

**Algorithm service** is the service that provides the algorithms and the preprocessing transformations for this run. Artifacts and trained models stay on the service that produced them. Later steps only list what that service offers.

Each row shows the service name, its address, and a status:

* **Online**
* **Offline**
* **Unknown** or **Checking**, while availability is still being read

**Recheck availability** runs the check again. An **Offline** service can still be selected: it may come back before you press **Train**. A **Built-in** chip marks the product service. **Registered** marks a service you added.

If only one service is available, it is selected for you. Confirm it with **Next**.

Changing the service clears the preprocessing, the algorithm, and any reused run you had already chosen.

<Info>
If the list is empty, the page reports that no algorithm service is reachable. An algorithm service must be configured before training can continue.
</Info>

## Data preparation

**Data preparation** chooses what happens to the data before it is split and trained. Three tabs are available:

* **New preprocessing**
* **Reuse preprocessing only**
* **Reuse split**

The two reuse tabs are available when the run is tied to a dataset version or to an equipment. Otherwise they stay disabled. Reuse is meant for comparing models trained on the same prepared data.

### New preprocessing

The pipeline starts from **Initial Input**, with the data type of the current source (time series, images, and so on).

With no step added, the page states that the dataset will be used as-is. **Add First Step**, **Add Step**, or **Add Next Step** opens **Add Preprocessing Step**. Pick a transformation from **Select Transformation**. The list only contains transformations that accept the type currently coming out of the pipeline. Each added step shows its **Input** type, its **Output** type, and, when present, a **Parameters** panel.

A step that does not accept the previous output blocks **Next** and shows an error. Remove that step or choose a compatible one. The close icon on a step removes it.

Leave a parameter blank to keep the transformation default. Only values you fill in are sent.

### Reuse preprocessing only

Pick one past preprocessing run. The right side shows the run id, when it was created, and the chain that was applied. **Next** stays disabled until a run is selected.

The fresh preprocessing is skipped. You still configure **Split data** on the next step.

If no past run exists yet, complete one training with **New preprocessing**. That run then appears in this list.

### Reuse split

Pick one past run that already includes both preprocessing and a split. The detail panel also shows the split strategy and the train, validation, and test shares.

**Next** skips **Split data** and opens **Training**. Both preprocessing and splitting are reused and are not run again.

## Split data

**Split data** divides the prepared data into training, validation, and test sets. This step is skipped when **Reuse split** is selected.

**Split strategy** is required. The choices are:

* **time** — default. Keeps the original order. Use this for a raw time series.
* **random**
* **stratified**

**Random seed** repeats the same split on a later run. The default is **42**.

**Train**, **Validation**, and **Test** start at **70%**, **15%**, and **15%**. The bar above the fields shows the resulting shares. If the three values do not add up to 100, they are treated as weights and normalised to 100%. **Train** must be greater than zero. Otherwise the step asks you to enter at least a non-zero Train value, and **Next** stays disabled.

Three switches sit under the ratios:

* **Shuffle before splitting**
* **Stratified on label**
* **Keep facts together** — samples that belong to the same fact stay in the same subset.

## Training

Set **Model name**. A name is filled in for you from the dataset (or the word `model`), the version, and the current date and time. You can replace it. The name is required.

Open **Algorithm** and pick one entry. You can search by name, task, or family, and filter the list with the family chips. The list only contains algorithms compatible with the data type produced by data preparation (or with the dataset type, when preprocessing is reused).

If the chosen algorithm expects a different input from the one data preparation produces, the step shows that mismatch and **Next** stays disabled. Remove the incompatible preprocessing step, or pick an algorithm that accepts the produced type.

When the algorithm has hyperparameters, they appear under its name. Leave a field blank to use the algorithm library default. Only the values you fill in are sent. A field marked required must be filled before **Next** is enabled.

Choosing an algorithm of a different task (for example from classification to regression) replaces the metrics on the next step with the defaults of the new task.

## Evaluation

**Evaluation** chooses the metrics computed after training. The chips depend on the task of the selected algorithm.

| Task               | Metrics you can turn on              | Selected by default        |
| ------------------ | ------------------------------------ | -------------------------- |
| Classification     | Accuracy, Precision, Recall, F1      | Accuracy, F1               |
| Regression         | MAE, MSE, R2                         | MAE, MSE, R2               |
| Anomaly detection  | Precision, Recall, F1                | Precision, Recall, F1      |

Click a chip to add or remove it. You can continue with none selected.

## Summary

**Review & train** repeats the choices: algorithm service, preprocessing, split, algorithm, model name, hyperparameters, and metrics. **Edit** on a card returns to that step. A reused preprocessing or split is marked **Reused** and will be skipped when the run starts. If no preprocessing step was added, the card says the raw data is used as-is.

**Train** closes this window and opens the run window.

## While the run is in progress

The run window is titled **Run**, followed by the model name. The header shows the phase, the algorithm, the dataset version when there is one, the background job number, and the elapsed time.

The phase is one of:

* **Queued**
* **Running**
* **Completed**
* **Failed**

Four cards follow the work:

1. **Preprocessing**
2. **Splitting data**
3. **Training**
4. **Evaluation**

Each card is **Queued**, **Running**, **Done**, **Failed**, **Reused from a previous run**, or **Not run**. A finished card shows how long that step took.

**Pipeline log** lists the messages of the run. **Copy** puts the log on the clipboard. When the run completes and metrics were requested, **Evaluation results** shows the values.

**Dismiss** (or **Close**, once the run has finished) hides the window. Dismissing a run that is still going does not stop it. A clock button at the bottom right of the platform reopens the same window. The job is also listed under [Background Jobs](/3.2/reporting/background-jobs).

When training succeeds, a notice confirms that the new model is available in the Models section. If the run fails, the notice asks you to read the pipeline log.
