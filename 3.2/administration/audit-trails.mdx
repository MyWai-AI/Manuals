#### Overview

The Audit Trails section provides a record of significant user and system actions that occur within the platform. It is designed to ensure accountability, traceability, and security by allowing administrators to review who performed a specific operation, what action was taken, and when it occurred.

The audit log captures operations that impact authentication, users, equipment, sensors, and measurement configurations.

#### Purpose

* Track platform usage for security and compliance.
* Detect unauthorized actions or access attempts.
* Support forensic investigation after configuration or data changes.
* Provide transparency and accountability for administrative activities.

#### Accessing the Audit Trails Page

1. In the left navigation menu of the platform, open the Administration section and click on the **Audit Trails** item.
2. Use filtering tools to locate specific actions by user, entity, or time interval.

#### Logged Actions

In this first version of the Audit Trail functionality, these are the actions recorded:

**User-related events**

* **User Create**: A new user account has been created.
* **User Login**: A user successfully logged in to the platform.
* **User Logout**: A user logged out of the platform.
* **User Unauthorized**: An unauthorized access attempt occurred.

**Equipment-related events**

* **Equipment Create**: A new equipment entry has been added.
* **Equipment Update**: Existing equipment details have been modified.
* **Equipment Delete**: Equipment entry has been removed.

**Equipment type events**

* **Equipment Type Create**: A new type of equipment has been defined.
* **Equipment Type Update**: Existing equipment type details have been modified.
* **Equipment Type Delete**: An equipment type has been removed.

**Sensor-related events**

* **Sensor Create**: A new sensor has been added.
* **Sensor Update**: Existing sensor details have been modified.
* **Sensor Delete**: A sensor has been removed.

**Measurement-related events**

* **Measure Create**: A new Measure entity has been created.
* **Measure Update**: A Measure entity has been modified.
* **Measure Delete**: A Measure entity has been removed.

**Measurement configuration events**

* **Measure Configuration Create**: A new measurement configuration has been created.
* **Measure Configuration Update**: A measurement configuration has been updated.
* **Measure Configuration Delete**: A measurement configuration has been deleted.

<Info>
These Measure Configuration events happen working on a Sensor or Custom Field advanced configuration.
</Info>

**Sensor measurement association events**

* **Sensor Measure Create**: A measurement has been associated with a sensor.
* **Sensor Measure Update**: The association between a sensor and a measurement has been updated.
* **Sensor Measure Delete**: A measurement association has been removed from a sensor.

#### Event information

The click on the magnifying glass icon will show details on the specific event:

* IP address of the user (when available)
* Actor and Entity identifiers
* Changes applied to the entity (old value vs new value), if applicable

#### Filtering

Audit entries can be filtered by:

* Time range
* Action type (e.g., _Sensor Create_, _User Login_, etc.)
* Affected equipment
* Actor type (User or Platform)
* The specific User that performed the action (in case the selected Actor type is User)

#### Export

Audit trails can be exported as a CSV file.
